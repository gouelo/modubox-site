# האתר החדש של מודובוקס

האתר של מודובוקס – מחסנים מודולריים, מבני שירותים וביתני שמירה (מחסני גלבוע מוסתרים כרגע).
עיצוב מינימליסטי: קטלוג מלא, סל קניות, הובלה והתקנה לבחירה, הזמנה בוואטסאפ ותשלום מאובטח בכרטיס אשראי דרך Z-Credit (ב־Vercel).

בנוי ב־Next.js + TypeScript + Tailwind, עם Framer Motion לאנימציות. הדפים סטטיים – מהירים וזולים לאחסון. ב־Vercel יש גם שרת קטן לתשלום (Z-Credit); ב־GitHub Pages האתר נבנה סטטי לגמרי, בלי תשלום באתר.

## איך משנים דברים באתר

**כמעט כל מה שצריך לשנות נמצא בתיקייה `data/`.** אין צורך לגעת בקוד.

| מה רוצים לשנות | איפה |
|---|---|
| מחירים, מידות, תיאורים, תמונות של מוצר | `data/products.json` |
| תוספות (חלון, דלת, מזגן...) ומחיריהן | `data/addons.json` |
| **מבצע החודש** (הפס הכתום בדף הבית) | `data/promo.json` |
| טלפון, וואטסאפ, מייל, כתובת, דירוג גוגל, קטגוריות מוסתרות | `data/site.json` |
| לוגואים של לקוחות קיימים | `data/clients.json` + `public/clients/` |
| ביקורות לקוחות | `data/reviews.json` |
| סרטונים (יוטיוב) | `data/videos.json` |
| תמונות בגלריה | `data/gallery.json` |
| שאלות נפוצות (בקבוצות, עם תמונות) | `data/faq.json` |
| **סרטון אנכי מהמפעל** בדף "קצת עלינו" | `data/site.json → factoryVideo` |
| תקנון | `content/terms.md` |
| אחריות | `content/warranty.md` |

> טיפ: אפשר פשוט לבקש מ־Claude / ChatGPT: "בקובץ data/products.json תעדכן את המחיר של מחסן 3×2 ל־7,900".

### סרטון מהמפעל (דף "קצת עלינו")

בדף "קצת עלינו", באזור "המפעל", יש מקום מוכן לסרטון אנכי (9:16) מהעבודה במפעל בעין חרוד. כל עוד אין סרטון, המקום מוסתר והתמונות מקרוב מתפרסות לכל הרוחב. כדי להציג סרטון ממלאים **אחד** מהשניים ב־`data/site.json → factoryVideo`:

```json
"factoryVideo": {
  "youtubeId": "abc123XYZ",          // מזהה של סרטון או Short ביוטיוב (מה שאחרי watch?v= או shorts/)
  "file": "",                        // או: קובץ mp4 בתיקייה public/videos, למשל "videos/factory.mp4"
  "poster": "",                      // תמונת פתיחה (לא חובה), למשל "videos/factory-poster.jpg"
  "caption": "עבודה במפעל שלנו בקיבוץ עין חרוד מאוחד"
}
```

> קובץ mp4 כדאי לשמור קטן (עד כ־20MB). סרטון ארוך או כבד – עדיף להעלות ליוטיוב ולשים את המזהה.

### שאלות נפוצות

ב־`data/faq.json` השאלות מחולקות לקבוצות (`groups`). לכל קבוצה כותרת ותמונה, ולכל שאלה `q` ו־`a`. אפשר להוסיף לשאלה `link` (קישור לעמוד), `media` (רשימת תמונות, או `"materials"` לתמונת החומרים עם התוויות), `cta: "custom-size"` (כרטיס ייעוץ למידה מיוחדת) ו־`open: true` (פתוחה כשהדף נטען). ב־`ratio` כותבים את יחס התמונה (למשל `"4/3"`) כדי שתוצג שלמה.

### מבצע החודש

בכל חודש מחליפים את המבצע בקובץ `data/promo.json` (ואין צורך לגעת בשום דבר אחר):

```json
{
  "enabled": true,
  "eyebrow": "מבצע החודש",
  "title": "כותרת המבצע",
  "text": "שורה אחת שמסבירה את המבצע",
  "endDate": "2026-11-30",
  "cta": { "label": "לפרטים בוואטסאפ", "href": "whatsapp", "whatsappText": "היי מודובוקס! אשמח לשמוע על מבצע החודש" }
}
```

- `enabled` – `true` מציג את הפס, `false` מסתיר אותו.
- `endDate` – היום האחרון של המבצע (שנה־חודש־יום). מהיום שאחריו הפס נעלם לבד. אפשר להשאיר ריק (`""`) למבצע בלי תאריך.
- `cta.href` – לאן הכפתור מוביל: `whatsapp` פותח וואטסאפ עם ההודעה שב־`whatsappText`, או כתובת של דף באתר, למשל `/shop/` או `/product/modubox-3x2/`.
- **כרגע יש בקובץ טקסט לדוגמה** ("כאן תופיע כותרת המבצע של החודש") – מחליפים אותו במבצע האמיתי.

### לקוחות קיימים, דירוג גוגל וקטגוריות מוסתרות

- **לוגואים של לקוחות:** קובץ PNG שקוף (באפור כהה, גובה 160 פיקסלים) בתיקייה `public/clients/`, ושורה בקובץ `data/clients.json` עם השם, שם הקובץ והמידות שלו.
- **דירוג גוגל:** `rating` ו־`reviewCount` בקובץ `data/site.json` (של הכרטיס "Modubox - מודובוקס" בגוגל). מעדכנים מדי פעם לפי מה שגוגל מציג.
- **המחסן המרחף ("עצבו את המחסן שלכם ב־3D"):** ניסוי – כפתור קטן בפינה התחתונה שמוביל לקונפיגורטור. כדי לכבות: `"floatingConfiguratorCta": false` בקובץ `data/site.json`. הטקסטים: `floatingCta` ב־`src/i18n/he.ts` ו־`en.ts`. התמונה: `public/cta/shed-3d.webp`.
- **הסתרת קטגוריה:** `hiddenCategories` בקובץ `data/site.json`. כרגע `["gilboa"]` – מחסני גלבוע לא מופיעים בקטלוג, אבל הנתונים שלהם נשארים. כדי להחזיר אותם: `"hiddenCategories": []`.
- **תגית "הנמכר ביותר":** השדה `badge` של המוצר בקובץ `data/products.json` (כרגע על 3×2, 4×3 ו־5×3).

### שינוי מחיר של מחסן

ב־`data/products.json` מוצאים את המוצר לפי `slug` (למשל `modubox-3x2`) ומשנים:

```json
"price": 7800,
```

כל המחירים בשקלים, **כולל מע"מ**, בלי פסיקים.

### מחירי הובלה והתקנה

לכל מוצר יש `fulfillment` משלו. כל אחת מהאפשרויות שיש לה מחיר מופיעה ללקוח בסל לבחירה:

```json
"fulfillment": {
  "pickup": 0,                    // איסוף עצמי (0 = חינם)
  "delivery": 300,                // הובלה בלבד
  "installation": null,           // התקנה בלבד
  "deliveryAndInstallation": 1000,// הובלה והתקנה
  "payToInstaller": false,        // true = משלמים למתקין ביום ההתקנה (לא נכלל בתשלום באתר)
  "note": "מצפון לעכו ומדרום לבאר שבע: תוספת 100 ₪."
}
```

`null` = האפשרות לא מוצעת למוצר הזה.

### ערך `null` = TODO

כשמחיר לא ידוע, כתוב `null`. באתר יופיע "מחיר בתיאום" והלקוח יופנה לוואטסאפ. **אף מחיר לא הומצא** – כל `null` הוא משהו שצריך להשלים.

### תוספות

> התוספות מוצגות בכל עמוד מחסן ב"בונה" לגודל של אותו עמוד (בלי שלב בחירת מידה): קודם בוחרים צבע פרופילים (לבן או שחור, תוספת `profile-color`), ואז צעד־אחר־צעד: דלתות וחלונות ← חשמל ומיזוג ← פנים ורצפה (רצפת WPC, מדפים, אוורור) ← סיכום. בסיכום יש כפתור שליחה בוואטסאפ וכפתור הוספה לסל. כל תוספת נכנסת לשלב לפי ה־`group` שלה (קבוצה חדשה תופיע בשלב "תוספות נוספות"). המחיר מתעדכן תוך כדי, והתוספות עוברות לסל, לתשלום ולהודעת הוואטסאפ. תוספת עם `price: null` מסומנת "מחיר בתיאום" ולא נספרת בסה"כ. תוספת עם `pricePerM2` (רצפת WPC: 120 ₪ למ"ר כולל התקנה) מתומחרת לפי שטח הרצפה של המחסן: `pricePerM2` × `widthM` × `depthM` מ־`products.json`, לכל צבע חוץ מ"ללא". דוגמיות צבע (`swatch`) יכולות להיות צבע (`#1d1f22`) או תמונה מתוך `public/images` (`floor/wpc-grey.webp`). בדף הבית, "התחילו להרכיב מחסן" פותח קודם בחירת מידה, ומשם לבונה של אותה מידה. סדר השלבים ושמותיהם: `src/lib/builder.ts`.

ב־`data/addons.json`. סוגים:

- `toggle` – כן/לא (למשל דלת כפולה)
- `qty` – כמות, עם `maxQty` (למשל חלונות)
- `choice` – בחירה מרשימה (למשל סוג מזגן)

איזה תוספות מופיעות במוצר – הרשימה `addons` בכל מוצר ב־`products.json`. מחיר שונה לתוספת במוצר מסוים – `addonPriceOverrides` (למשל `"vent-grill": 150`).

### כפתור העיצוב בתלת־ממד

בדף הבית, בקטלוג ובכל עמוד מוצר יש כפתור "רוצים לעצב את המחסן שלכם בתלת־ממד?". ההגדרות ב־`data/site.json`, תחת `design3d`:

- `url` – כתובת הקונפיגורטור. את `{model}` האתר מחליף בדגם של המוצר (`3x2`, `4x1`...), כך שכל עמוד מוצר פותח את הקונפיגורטור על המידה שלו. בדף הבית ובקטלוג הכפתור פותח אותו בלי דגם. `url` ריק = הכפתור לא מוצג.
- `script` – סקריפט ההטמעה (`embed.js`) של הקונפיגורטור. הוא נטען בכל דף, ובלחיצה על הכפתור פותח את הקונפיגורטור בחלונית צד מעל הדף (בטלפון – מסך מלא, וכפתור "חזרה" סוגר אותה). `market` – השוק (`il`).
- הדגם נגזר מהמידות של המוצר (`widthM`×`depthM`), רק למחסני מודובוקס ורק במידות שיש בקונפיגורטור (1–4×1, 2–6×2, 3–6×3). לשנות דגם למוצר מסוים: מוסיפים לו ב־`products.json` את `"configuratorModel": "3x2"` (או `null` כדי לפתוח בלי דגם).
- `label` – הטקסט על הכפתור.

### מוצר חדש

מעתיקים מוצר קיים ב־`products.json`, משנים `slug` (באנגלית, בלי רווחים) ואת שאר הפרטים. העמוד שלו נוצר אוטומטית בכתובת `/product/<slug>/`. בכל עמוד של מחסן מודובוקס יש כפתור "רוצים לעצב את המחסן שלכם בתלת־ממד?".

## תמונות ולוגו

- **הלוגו:** `public/brand/logo.svg` (ו־`logo-white.svg` לרקע כהה, `favicon.svg` ו־`apple-touch-icon.png` לאייקון). שורטטו מחדש מהלוגו המקורי, שנשמר ב־`design/modubox-logo.jpg`.
- **תמונות מוצרים:** שמים את הקובץ ב־`public/images/photos/` ורושמים את השם ב־`images` של המוצר: `"photos/my-photo.webp"`. התמונה הראשונה היא הראשית.
- **התמונות כרגע** נלקחו מהאתר הישן. **בגלריה (`gallery.json`) רק תמונות אמיתיות**, בלי הדמיות. כדאי להוסיף צילומים חדשים ואיכותיים.
- גדלים מוקטנים לכל תמונה (לטעינה מהירה) נוצרים אוטומטית בכל `npm run dev` / `npm run build`. אין צורך לעשות כלום.
- עדיף webp או jpg, ברוחב 1600–2400 פיקסלים.
- הדמיות שיואל בחר לדף הבית ולדפי המוצר נמצאות ב־`public/images/renders` (הגלריה נשארת עם תמונות אמיתיות בלבד).


## העלאה לאוויר

### תצוגה מקדימה – GitHub Pages

כל דחיפה ל־`main` בונה את האתר ומעלה אותו לענף `gh-pages` (`.github/workflows/pages.yml`), שמוצג בכתובת
`https://gouelo.github.io/modubox-site/`.

### האתר האמיתי – Vercel (מומלץ)

1. נכנסים ל־[vercel.com](https://vercel.com) עם חשבון ה־GitHub.
2. **Add New → Project** ← בוחרים את `modubox-site` ← **Deploy**. אין צורך לשנות הגדרות.
3. מעכשיו כל שינוי שנדחף ל־GitHub עולה לאוויר תוך דקה.

### Vercel + Z-Credit (תשלום באתר)

התשלום עובד רק ב־Vercel (ב־GitHub Pages אין שרת). הלקוח בוחר 1–12 תשלומים רגילים (לא קרדיט), עובר לעמוד התשלום המאובטח של Z-Credit (כרטיס, Apple Pay, Google Pay) וחוזר לעמוד "התשלום התקבל" או "התשלום לא הושלם".

**משתני סביבה** – ב־Vercel: **Project → Settings → Environment Variables** (לסמן Production, ואם רוצים גם Preview), ואז **Redeploy**:

| שם | ערך |
|---|---|
| `ZCREDIT_WEBCHECKOUT_KEY` | המפתח מהפאנל של Z-Credit: הגדרות עסק → הגדרות סליקה → WebCheckout → "החלף מפתח". **סודי – לא שומרים אותו בקוד, בצ'אט או במייל.** |
| `ZCREDIT_TERMINAL_NUMBER` | `2071556014` |

בלי המשתנים האתר לא נשבר: בשלב התשלום מופיעה הודעה, כפתור "אישור הזמנה" וכפתור וואטסאפ. דוגמה: `.env.example`.

**בפאנל של Z-Credit:** למלא את פרטי העסק, ליצור את מפתח ה־WebCheckout, ולוודא שהאפשרויות Apple Pay ו־Google Pay מסומנות בהגדרות הסליקה.

**איך זה עובד (למפתחים):**
- `POST /api/checkout/` (`src/app/api/checkout/route.api.ts`) מקבל רק מזהי מוצרים, תוספות, בחירת הובלה ופרטי לקוח, **ומחשב את המחיר מחדש בשרת** מתוך `data/` (`src/lib/checkout.ts`). מחיר שנשלח מהדפדפן לא נלקח בחשבון. ואז קורא ל־CreateSession של Z-Credit (`src/lib/zcredit.ts`) ומחזיר את כתובת עמוד התשלום.
- `POST /api/checkout/callback/` – Z-Credit מודיע על תשלום. השרת בודק מול Z-Credit (GetSessionStatus) שהעסקה הצליחה, על הסכום המלא ועל ההזמנה הזו, ורק אז רושם "ORDER PAID" ביומן.
- הזמנה עם פריט "מחיר בתיאום" לא משולמת באתר – נשלחת לנציג.
- קבצים בשם `route.api.ts` נבנים רק כשיש שרת; בבניית GitHub Pages (`GITHUB_PAGES=true`) הם מושמטים.
- **איפה רואים הזמנות:** Vercel → Project → **Logs**, לחפש `[checkout]`.
- **בדיקה:** הטרמינל אמיתי (לא סביבת ניסיון). עסקת בדיקה = חיוב אמיתי: לשלם סכום קטן מאייפון ומאנדרואיד, ואז לבטל את העסקה בפאנל.
- שימו לב: ב־Preview של Vercel מופעלת כברירת מחדל הגנת התחברות (Deployment Protection), ואז ההודעה של Z-Credit לא מגיעה לשרת. בודקים תשלום על הדומיין של Production.

### קודי קופון (הנחות)

בסל ובעמוד התשלום יש שדה "קוד קופון". הקודים **לא** נשמרים בקוד (המאגר ציבורי), אלא במשתנה סביבה ב־Vercel בשם `MODUBOX_COUPONS`. השרת בודק את הקוד ומחשב את ההנחה בעצמו.

**הפורמט:** `קוד=הנחה`, וקופונים מופרדים בנקודה־פסיק `;`:

```
PINUK10=10%;SALE500=500
```

- `10%` – אחוז הנחה. `500` – הנחה של 500 ₪.
- אפשר להוסיף אחרי פסיק:
  - `min=10000` – רק בהזמנה של 10,000 ₪ ומעלה.
  - `until=2026-12-31` – תקף עד היום הזה (כולל).
  - `delivery` – ההנחה חלה גם על ההובלה וההתקנה (בלי זה: רק על המוצרים).
- דוגמה מלאה: `PINUK10=10%;VIP15=15%,min=10000,until=2026-12-31;HOVALA=900,delivery`
- אותיות גדולות או קטנות – לא משנה. רווחים לא מפריעים. ההנחה אף פעם לא מורידה את התשלום מתחת ל־1 ₪.

**איך מוסיפים או משנים קופון:**
1. Vercel → הפרויקט `modubox-site` → **Settings** → **Environment Variables**.
2. אם עוד אין: **Add New** ← Key: `MODUBOX_COUPONS`, Value: הקודים (למשל `PINUK10=10%;SALE500=500`) ← לסמן Production ← **Save**. אם כבר יש: ⋯ ← **Edit** ← לשנות את הערך ← **Save**.
3. **Deployments** ← בפריסה העליונה ⋯ ← **Redeploy**. השינוי תופס רק אחרי Redeploy.

בלי המשתנה השדה מופיע, אבל כל קוד נדחה ("הקוד הזה לא קיים").

### מוצר בדיקה ב־1 ₪

לבדיקת תשלום אמיתי מהטלפון: `https://modubox-site.vercel.app/p/test-nhsxjlenh4/` (נסתר: לא בקטלוג, לא במפת האתר ולא בגוגל). מוסיפים לסל ומשלמים 1 ₪, ואז מבטלים את העסקה בפאנל של Z-Credit. לכיבוי: ב־`data/test-product.json` לשנות `"enabled": true` ל־`false`.

### חיבור הדומיין modubox.com

1. ב־Vercel: **Project → Settings → Domains** ← מוסיפים `modubox.com` ו־`www.modubox.com`.
2. Vercel מציג רשומות DNS (בדרך כלל `A 76.76.21.21` ל־`modubox.com` ו־`CNAME cname.vercel-dns.com` ל־`www`).
3. אצל רשם הדומיין (או ב־Wix, אם הדומיין רשום שם: Domains → Manage DNS) מעדכנים את הרשומות. תוך כמה שעות האתר החדש עולה על הדומיין.

> לפני ההחלפה כדאי לבדוק שכתובות חשובות מהאתר הישן מפנות לחדש (למשל דרך `redirects` ב־Vercel), כדי לא לאבד מיקום בגוגל.

## ממשק הניהול (/admin)

הזמנות, לקוחות, סטטוסים, מועדי אספקה, הערות וייצוא לאקסל, בכתובת `/admin` באתר ב־Vercel (לא ב־GitHub Pages). כל הזמנה נשמרת במסד נתונים כשהלקוח עובר לתשלום, ומסומנת כשולמה רק אחרי אימות מול Z-Credit. על כל הזמנה ששולמה נשלח מייל לעסק.

מה צריך ב־Vercel: מסד נתונים Neon (**Storage → Create Database → Neon**), ומשתני הסביבה `ADMIN_PASSWORD`, `RESEND_API_KEY` ו־`ORDER_EMAIL_TO`. מייל אישור הזמנה ללקוח יוצא רק אחרי אימות דומיין ב־Resend והגדרת `MAIL_FROM`. בלי `ADMIN_PASSWORD` הממשק נעול. האפיון המלא וההוראות: [docs/admin-spec.md](docs/admin-spec.md).

## Google Tag Manager ואירועים

‏מכולת GTM: `GTM-MB2W45D` (בקובץ `src/lib/analytics.ts`). היא נטענת **רק באתר הייצור ב־Vercel** (`VERCEL_ENV=production`), לא בתצוגות מקדימות ולא ב־GitHub Pages. משתנה הסביבה `NEXT_PUBLIC_GTM_ID` גובר עליה: מזהה מכולה אחר, או `off` כדי לכבות.

‏האירועים שנשלחים ל־dataLayer (בשמות של GA4, בלי שם, טלפון או מייל של לקוח):

| אירוע | מתי | פרמטרים |
|---|---|---|
| `whatsapp_click` | לחיצה על כל קישור וואטסאפ | `link_url` (בלי טקסט ההודעה), `link_text` |
| `phone_click` | לחיצה על כל קישור טלפון | `link_url` (`tel:…`), `link_text` |
| `generate_lead` | שליחת טופס יצירת קשר, או הזמנה בלי תשלום אונליין | `form_name` (`contact` / `order`), `item_name` (מוצר, אם יש), `currency` ו־`value` (בהזמנה) |
| `add_to_cart` | הוספה לסל | `ecommerce: {currency: "ILS", value, items}` |
| `begin_checkout` | כניסה לקופה עם סל | `ecommerce: {currency: "ILS", value, items}` |
| `purchase` | עמוד ההצלחה, רק אחרי שהשרת אימת מול Z-Credit שההזמנה שולמה; פעם אחת להזמנה | `ecommerce: {transaction_id, currency: "ILS", value, coupon?, items}` |

‏`items`: ‏`item_id` (ה־slug), ‏`item_name`, ‏`item_category`, ‏`price` (מוצר + תוספות, ליחידה), ‏`quantity`. ‏`value` כולל הובלה והתקנה שמשולמות באתר, וברכישה הוא הסכום ששולם בפועל (אחרי קופון).

## בלוג, הפניות מהאתר הישן ועוגיות

‏**בלוג (/blog/):** כל 22 הפוסטים מהבלוג של Wix, כקבצי Markdown ב־`content/blog/<slug>.md` (בראש כל קובץ: כותרת, תיאור, תאריך ותמונה). התמונות ב־`public/images/blog/`, והמידות שלהן ב־`data/blog-images.json`. פוסט חדש: מעתיקים קובץ קיים ומשנים. הבלוג בעברית בלבד, עם קישור בתחתית האתר ורצועה קטנה "מהבלוג" בדף הבית.

‏**הפניות 301 מהאתר הישן:** כל כתובת של modubox.com ב־Wix (מוצרים, עמודים, פוסטים, קטגוריות, ותבניות הכתובות של Wix) מופנית לדף המתאים. הטבלה המלאה ב־[docs/redirects.md](docs/redirects.md), הנתונים ב־`data/redirects.json` (אחרי שינוי: `node scripts/redirects-doc.mjs`). עובד ב־Vercel בלבד, אחרי שהדומיין עובר.

‏**עוגיות ופרטיות:** הודעת עוגיות (אישור / דחייה / הגדרות) ו־Google Consent Mode v2: עד שהגולש מסכים, מדידה ופרסום כבויים. הבחירה נשמרת בדפדפן, ו"הגדרות עוגיות" בתחתית האתר פותח אותה שוב. מדיניות הפרטיות ב־`content/privacy.md` (תאריך העדכון ב־`src/views/TextPage.tsx`).

## אנגלית (/en/)

האתר בעברית נשאר בכתובות הרגילות; האנגלית נמצאת תחת `/en/` עם אותם דפים בדיוק. הכפתור בכותרת (דגל) עובר לאותו דף בשפה השנייה.

- **טקסטים של האתר** (כפתורים, כותרות, הודעות): `src/i18n/he.ts` ו־`src/i18n/en.ts`. כל מחרוזת חדשה מוסיפים **בשני הקבצים** באותו מקום – הבדיקה `tests/i18n.test.ts` נכשלת אם חסר מפתח, או אם נשארה עברית באנגלית.
- **תוכן** (מוצרים, תוספות, שאלות נפוצות, ביקורות, סרטונים, גלריה, לקוחות, פרטי עסק): העברית ב־`data/*.json`, והתרגום ב־`data/en/*.json` (לפי slug / מזהה / סדר). מחירים, מידות ותמונות נלקחים תמיד מהקובץ העברי – משנים רק שם.
- **מבצע החודש:** ב־`data/promo.json` יש בלוק `en` – לעדכן אותו יחד עם העברית.
- **תקנון, אחריות ונגישות באנגלית:** `content/en/*.md`.
- הקהל: דוברי אנגלית שגרים וקונים בישראל – מחירים ב־₪, מטרים, הובלה בישראל.

## נגישות

האתר עומד ברמה AA של תקן ישראלי 5568 (WCAG 2.0), כנדרש בתקנות הנגישות לשירות (תקנה 35).

- **הצהרת הנגישות:** `content/accessibility.md` ו־`content/en/accessibility.md` (דפים `/accessibility/` ו־`/en/accessibility/`, קישור בפוטר). שם הרכז/ת ותאריך העדכון ב־`site.json → accessibility`. כל שינוי משמעותי באתר – לעדכן את התאריך.
